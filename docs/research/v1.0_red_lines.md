# v1.0 Red Lines (Internal)

> **Historical artifact:** these positions describe a superseded draft. Model v1.2 and the current paper replace them wherever they conflict.

**Purpose**: Our non-negotiable or very strongly held positions on the current v1.0 package. These are the hills we are prepared to defend unless reviewers provide compelling counter-evidence or alternative framing that clearly improves the paper.

We will treat these as strong starting positions when processing feedback, not as absolute vetoes. The goal is intellectual honesty and quality, not defensiveness.

## 1. 2×2 Framework Must Remain First-Class and Early

- The 2×2 (Direct/Indirect × Upstream/Downstream) must be introduced as a structural, first-order feature of the model, not as an afterthought or refinement added later.
- It should appear in the research questions, contribution statement, and early model description.
- We will push back on any suggestion that reduces it to "optional context" or moves detailed discussion only to section 8 or the appendix.

**Why we believe this strongly**: The 2×2 is not a small perturbation — it changes which cost components dominate and by how much. Treating it as secondary would misrepresent the model we actually built and implemented.

## 2. Reproducibility Claims Must Stay Prominent But Honest

- We will keep a clear, dedicated reproducibility story (3.8 recipe, formal statement, replication subsection, researcher exports).
- We will not water it down to vague claims like "the model is transparent."
- At the same time, we will not over-claim (e.g. we will not say the current version is "fully empirically validated" — it is a measurement instrument with traceable parameters).

**Why we believe this strongly**: One of the distinctive contributions of this work is that it treats the calculator itself as a formal, exportable measurement model. Diluting that would lose a major strength. Overstating it would damage credibility.

## 3. Core Propositions (P1–P4) Must Stay Tied Directly to the Implementation

- The four main propositions should remain explicitly derived from the 2×2 mechanics in the code (tcoMultiplier = 1.62 in Direct+Upstream, +22% boosts, 1.85× executive loading, etc.).
- We will resist turning them into generic statements disconnected from the specific multipliers and step-level rules.

**Why we believe this strongly**: These propositions are not free-floating hypotheses — they are mechanical predictions of the current implementation. Decoupling them would make the "testable" part weaker.

## 4. Limitations Section Should Remain Honest About the Current State

- We will keep the explicit statement that no primary data has been collected yet and that the 2×2 multipliers are the highest-priority parameters for future calibration.
- We will not add hedging language that makes the model sound more empirically grounded than it currently is.

**Why we believe this strongly**: Intellectual honesty is central to the positioning of this project. Softening the limitations would undermine trust with potential collaborators and reviewers.

---

**How we will use this document**:
- When processing feedback, any suggestion that directly contradicts one of these will be flagged.
- We will first try to understand the reviewer's concern.
- Only then will we decide whether to defend, reframe, or (rarely) concede.
- This document is private until we decide otherwise.

**Counter-argument seeds** (to be expanded):
- 2×2 first-class: The implementation in `getDimensionMultipliers` + per-step rules in derive* functions directly produces different dominant costs by quadrant. Treating 2×2 as secondary would make the paper describe a weaker model than the one we actually coded and exported.
- Reproducibility: The live export JSON contains the exact multiplier vector, derived values, and sources. This is stronger than most empirical papers can offer at the model stage.
- Propositions tied to implementation: P1–P4 are falsifiable predictions of the current v1.1 functions. Decoupling them would turn them into generic statements anyone could make without the specific 1.62 / 1.22 / 1.85× mechanics.
- Limitations honesty: We explicitly state no primary data yet and flag the 2×2 multipliers as calibration priorities. This matches the actual state of the artifacts.
